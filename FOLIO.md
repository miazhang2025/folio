# Folio

**Last updated:** May 9, 2026
**Status:** scaffolded · standalone UI running · extension stubs in place

A tool that turns your scattered Claude conversations into a knowledge map.
You see what you've been thinking about, how it evolved, and what you
left unfinished. Companion to Cabbage Farm.

---

## Why this exists

When you use Claude heavily, conversations pile up across tabs. There's
no way to see them as a whole — you can only paw through them one at a
time. The pile contains a real picture of your thinking but it's invisible.

Folio surfaces it.

---

## One-liner

> Folio reads your Claude conversations and grows them into a living
> knowledge map — nodes per topic, notes per node, dispatches per week.

---

## Three layers (the mental model that holds everything together)

1. **L1 — Conversations** · raw transcripts pulled from claude.ai
2. **L2 — Nodes** · semantic clusters; each node has a synthesis-style note
3. **L3 — Mindmap** · the interactive view; the user-facing surface

Everything in the codebase organizes around these three. When in doubt
about where a piece of logic lives, ask which layer it belongs to.

---

## What Folio is NOT

To stay focused, here's what we're explicitly not building:

- A Claude chat UI — Folio reads, doesn't replace
- A Notion competitor — notes are auto-generated, not hand-written
- A real-time collaboration tool — single-user, local-first
- A note-taking app with manual links — links emerge from the data
- An Obsidian replacement — actually emits compatible markdown so it
  can sit alongside Obsidian if the user wants

## Tech stack

| Layer | Choice | Why |
|---|---|---|
| Framework | **React 18 + TypeScript** | Mia knows it; ecosystem is best for D3 + Three.js integration |
| Build | **Vite + CRXJS plugin** | Fast HMR; CRXJS handles the manifest-v3 pain |
| Styling | **Tailwind CSS** | Fast iteration; matches the mockup approach |
| State | **Zustand** | UI state with minimal boilerplate; works across extension contexts |
| Local data | **Dexie.js (IndexedDB)** | Best ergonomics for structured local data; `liveQuery` is reactive |
| Extension prefs | **chrome.storage.local** | API key, last-sync timestamp, etc. |
| Mindmap | **D3-force + native SVG** | Free node styling; clean data flow; future 3D upgrade path stays open |
| LLM | **Anthropic SDK (client-side)** | v0 calls API directly with user's key; backend later if needed |
| Embeddings | **OpenAI `text-embedding-3-small` via fetch** | Cheap, good; Anthropic doesn't expose embeddings yet |
| Clustering | **HDBSCAN via WASM port** OR **Claude-as-clusterer** | Decide based on data scale at v0.5 — see open questions |

### What we're not using

- **Next.js / Remix** — server-side rendering is irrelevant for a
  client-only local-first app
- **Redux / MobX** — overkill for our state shape
- **react-flow** — too heavy, opinionated; SVG + D3 gives full control
- **Drizzle / Prisma** — no SQL backend; Dexie is the database
- **A backend** — not until we ship to other users

## Data schema

The schema is the spine. Get this right early; it'll be everywhere.

### `conversations` table (Dexie)

```ts
interface Conversation {
  id: string;                  // claude.ai's UUID
  title: string;               // claude.ai's autogenerated title
  created_at: number;          // unix ms
  updated_at: number;          // unix ms
  project_id: string | null;   // claude.ai project, if any
  model: string;               // 'claude-opus-4-5', etc.
  message_count: number;
  messages: Message[];         // full transcript stored inline
  imported_from: 'extension' | 'export_zip';
  last_synced: number;
}

interface Message {
  id: string;
  role: 'user' | 'assistant';
  content: string;             // markdown text
  created_at: number;
  attachments?: Attachment[];
}
```

### `nodes` table

```ts
interface Node {
  id: string;                  // generated, e.g. 'cassette-jury'
  label: string;               // human-readable, e.g. 'Cassette Jury'
  family: 'creative' | 'work' | 'life' | 'admin';
  conversation_ids: string[];  // many-to-many; one conversation can be in multiple nodes
  position?: { x: number; y: number };  // user-pinned position; null = auto-layout
  recency: 'now' | 'recent' | 'past';   // computed from updated_at
  created_at: number;
  last_synthesized: number;    // when synthesize() last ran for this node
  manual_edits?: {
    label_override?: string;
    family_override?: string;
    pinned?: boolean;
  };
}
```

### `distills` table (cache for L2 step 1)

```ts
interface Distill {
  conversation_id: string;
  node_id: string;             // distills are per-(conv, node) pair
  conversation_hash: string;   // hash of message contents; invalidates cache when conv changes
  data: DistillData;           // the JSON output of the distill prompt
  created_at: number;
}

interface DistillData {
  subject: string;
  decisions: { what: string; status: 'settled' | 'tentative' | 'deferred' }[];
  facts: string[];
  open_questions: string[];
  advice_not_taken: { claude_said: string; mia_chose: string; her_reason: string | null }[];
  emotional_texture: string | null;
}
```

### `notes` table (cache for L2 step 2)

```ts
interface Note {
  node_id: string;             // primary key
  markdown: string;            // the rendered note
  digest_hashes: string[];     // hashes of distills used; invalidates when distills change
  created_at: number;
}
```

### `dispatches` table (weekly digests)

```ts
interface Dispatch {
  id: string;                  // 'dispatch-2026-W19'
  week_start: number;
  week_end: number;
  active_node_ids: string[];
  emerged_node_ids: string[];
  keywords: string[];
  narrative: string;
  ignored_advice: IgnoredAdvice[];
  created_at: number;
}
```

## L2 synthesis pipeline

See `src/llm/pipeline.ts` for the orchestration stub.

### Pipeline shape

```
[Conversations in node] → distill (parallel) → distills cached
                                ↓
                         synthesize (one call) → note cached
                                ↓
                         render in right panel
```

### Three prompts, each in `src/llm/prompts/`

- `validate.ts` — Step 0; runs only when cluster size ≥ 5
- `distill.ts` — Step 1; one call per conversation per node
- `synthesize.ts` — Step 2; one call per node

### Caching rules

- **Distill** cache key: `hash(conversation_messages) + node_id` —
  invalidate when either the conversation grows or the node assignment changes
- **Note** cache key: `set(distill_hashes)` — invalidate when any
  member distill changes

### Cost target

- Distill: ~$0.005 per conversation (Haiku) or ~$0.02 (Opus)
- Synthesize: ~$0.02 per node
- Cold-start for ~250 conversations / 30 nodes: **~$2-5**
- Steady state (weekly increment): **<$0.10/week**

Ship with Haiku for distill, Opus for synthesize.

## Open questions (decisions to make later, not now)

### How does clustering actually happen?

**Path A — Embedding + HDBSCAN.** Embed conversations, cluster with HDBSCAN.
**Path B — Claude as clusterer.** Feed Claude titles + first messages, ask it to group them.

**Decision deferred until v0.5.** Build Path B first; switch if it breaks at scale.

### Where do we live for non-Mia users?

Pure Chrome extension | Web app + manual JSON upload | Both.
**Deferred until after self-use proves the product.**

### How are families assigned?

Initially: Claude tags conversations into creative/work/life/admin.
Eventually: user-defined taxonomy.
**Deferred until v1.**

### Privacy boundary if we ever store data server-side

Conversation content is very sensitive. Encryption-at-rest, no content in error logs,
user-controlled deletion.
**Deferred until we have a non-trivial reason to leave the client.**

## Working notes — places things tend to go wrong

- **claude.ai's DOM/API will change** — anything fragile must have an
  obvious failure mode. Log loudly when scraping breaks.
- **IndexedDB has weird quota limits** — ~50MB before browser starts
  asking permission. Plan to compress message content (lz-string).
- **Service workers in extensions don't keep state across restarts** —
  any sync logic must persist its position in `chrome.storage`.
- **CSP on claude.ai blocks injecting scripts** — content script must
  use `chrome.runtime.sendMessage` to talk to the background worker.
- **Anthropic API key in browser = visible in DevTools** — fine for
  self-use; must move calls behind a proxy before shipping to others.

## Glossary

- **Folio** · the product
- **Node** · a topic; a cluster of related conversations
- **Note** · the synthesized markdown for one node
- **Distill** · cached digest of one conversation (within one node)
- **Synthesize** · the LLM call that combines distills into a note
- **Dispatch** · weekly digest, like a newsletter from your archive
- **Lens** · the family filter (creative / work / life / admin)
